# สคีมา D1 — แอปโรงขวด v2 (ฐาน `pk-v2` · แยกจากโรงน้ำเด็ดขาด)

> ต้นฉบับคือไฟล์ใน `v2/db/migrations/` — ไฟล์นี้อธิบาย "ทำไม" ของทุกตาราง
> ใส่ migration ในเครื่อง: เทสต์/เครื่องนักพัฒนาใส่ให้เอง (`tests/helpers/d1.mjs › migrate`) · ของจริง: `wrangler d1 migrations apply` (CI ทำให้)

## ข้อตกลงทุกตาราง

| เรื่อง | กติกา | กันด้วย |
|---|---|---|
| เวลา | `*_at` = ISO UTC แบบ `toISOString()` ยาว 24 ตัว (`2026-11-16T03:04:05.678Z`) | CHECK ความยาว/ตำแหน่ง `T` `Z` |
| วันที่ | `*_day` = วันไทย `YYYY-MM-DD` (UTC+7 คงที่ — `server/core.mjs › thaiDay`) · รอบข้ามเที่ยงคืนมีวันเริ่ม/วันปิดแยกกัน | CHECK ความยาว |
| เงิน | `*_satang` = จำนวนเต็มสตางค์ · ไม่มีราคา = `NULL` (ไม่ใช่ 0) | `CHECK (typeof(x) = 'integer')` |
| จำนวนของ | `*_pcs` = จำนวนเต็ม "ใบ/ชิ้น" · หน้างานนับถุง → เก็บ `bags` + `per_bag` ณ ตอนลง + `qty_pcs` ที่คิดแล้ว | CHECK `qty_pcs = bags × per_bag + extra_pcs` |
| ลบ | **ไม่มี DELETE** — ยกเลิก/ย้อน = พลิกสถานะ | trigger `no_delete_<ตาราง>` ทุกตาราง (0011) · ตัวแปลง ops ไม่มีทางสร้าง DELETE · D1 จำลองในเทสต์ปฏิเสธ |
| สมุด | `audit_log` · `stock_moves` · `price_history` · `device_readings` เขียนเพิ่มอย่างเดียว | trigger `no_update_<ตาราง>` |
| แก้พร้อมกัน | `version` (optimistic lock) — แก้จาก version ที่เห็น · ไม่ตรง = 409 | ด่าน `_guard` ใน batch เดียวกัน (`server/db.mjs › guardSql`) |
| ค่าสถานะ/ประเภท | ตรวจกับตาราง `vocab` (kind = `<ตาราง>.<คอลัมน์>`) | trigger `vocab_<ตาราง>_<คอลัมน์>_ins/_upd` (0011) — **โมดูลเพิ่มค่าใหม่ = `INSERT INTO vocab` ใน migration ของตัวเอง ไม่ต้องรื้อตาราง** |
| ที่มา | `src` = `v2` (ลงจากแอป) · `pk:<แท็บ>` / `legacy:…` / `acct:<แท็บ>` (นำเข้า) · `ref:…` (ทะเบียนใน repo) · `demo` (สมมติ) · `ticket` (ลงทะเบียนจากตั๋ว) | — |
| รหัสแถว | สุ่มเรียงตามเวลา (`newId`) — **รหัสไม่ขึ้นจอ** อ้างด้วย ร้าน·วันที่·ยอด·ใคร · รหัสอยู่บรรทัด "รหัสอ้างอิง" จาง ๆ ในรายละเอียดที่เดียว | — |
| PIN | **ไม่มีคอลัมน์ PIN ที่ไหนเลย** — มีแค่ `staff.pin_fp` (ลายนิ้วมือ HMAC ด้วยกุญแจที่อยู่ใน GAS เท่านั้น) | เทสต์ `schema.test.mjs` + `import.test.mjs` สแกนทั้งฐาน |
| foreign key | เปิด (ค่าตั้งต้นของ D1) | `PRAGMA foreign_keys = ON` ในเทสต์ |

## ช่วงเลข migration (ห้ามชนกัน — แต่ละแชทใช้ช่วงของตัวเอง)

| ช่วง | เจ้าของ | ตอนนี้ |
|---|---|---|
| 0001–0099 | Foundation | 0001–0011 |
| 0100–0199 | ทีมผลิต | 0100 |
| 0200–0299 | ออฟฟิศ | — |
| 0300–0399 | สกรีน + ส่งของ | 0300 |
| 0400–0499 | ประธาน + บัญชี | — |

**กติกาเพิ่มของ**: เพิ่มคอลัมน์ = `ALTER TABLE … ADD COLUMN …` ใน migration ช่วงของตัวเอง (คอลัมน์ใหม่ต้องมี DEFAULT) · เพิ่มตาราง = ใส่ trigger `no_delete_<ตาราง>` เองในไฟล์เดียวกัน (เทสต์แดงถ้าลืม) + ลงทะเบียนใน `server/db.mjs › registerTable()` (คีย์หลัก + ค่าที่ใช้ "ย้อนการเพิ่มแถว") · ห้ามแก้ไฟล์ migration ที่ขึ้นของจริงแล้ว · ห้ามแก้ไฟล์ช่วงของคนอื่น

## 0001_core — ของกลาง

| ตาราง | ทำไม |
|---|---|
| `_guard` | ตารางว่างที่ใส่ได้แค่ `code=''` — ใช้ทำ "ด่าน" ใน batch: `INSERT … SELECT 'v' WHERE NOT EXISTS(แถว version เดิม)` = ล้มทั้งชุด (SQLite นอก trigger ใช้ RAISE ไม่ได้) |
| `vocab` | คลังค่าที่อนุญาตทุกช่องสถานะ/ประเภท + ป้าย (`label`) + สีป้าย (`tone`: ok/warn/bad/brand/mute) + รายการเหตุผล (`reason.*` = ชิปในแผ่นยืนยัน) — หน้าเว็บได้ไปทั้งก้อนจาก `system.me` |
| `settings` | ค่าตั้งที่ไม่ใช่ความลับ (ย้อนได้กี่ ชม. · รอบค้างกี่ ชม. = ธง · รุ่นหน้าเว็บขั้นต่ำ) — ประธานแก้ผ่าน `setting.set` |
| `roles` | 6 บทบาท = 6 แอป + ชื่อแผนกในชีต Staff ที่จับคู่ (`ออฟฟิศ→office` …) |
| `staff` · `staff_roles` | พนักงานจากชีต Staff (ชีต/บอร์ดบริหารเป็นตัวจริงของทะเบียน) · ไม่มี PIN · `pin_fp` + `pf_at` = ตั๋วเก่าตายเมื่อ PIN เปลี่ยน · บทบาทหลายอันต่อคนได้ · ถอดบทบาท = `active=0` |
| `audit_log` | ทุก action ที่เขียน: 1 แถวต่อ 1 การเปลี่ยน (ใคร=จากตั๋ว · ชื่อเล่น ณ ตอนนั้น · บทบาทที่ใช้ · action · ตาราง/แถว · ค่าก่อน/หลัง (เฉพาะช่องที่เปลี่ยน) · เหตุผล · รหัสคำขอ · ย้อนของแถวไหน) อยู่ใน batch เดียวกับข้อมูลเสมอ |
| `idempotency` | กันกดซ้ำ: กุญแจที่หน้าเว็บสร้างต่อการกด 1 ครั้ง → ผลลัพธ์เดิม · กุญแจเดิมแต่เนื้อต่าง/คนต่าง = ปฏิเสธ · insert อยู่ใน batch เดียวกับข้อมูล (สองคำขอพร้อมกัน ตัวหลังชน PRIMARY KEY แล้วได้ผลของตัวแรก) |
| `undo_log` | "ย้อน" ของกลาง: คำสั่งพลิกกลับที่คิดไว้ตอนบันทึก (`ops_json`) — ย้อนได้เมื่อยังไม่เคยย้อน · ไม่เลยเวลา · คนเดิม/ประธาน · **ทุกแถวที่บันทึกยังเป็น version เดิม** (ขั้นถัดไปแตะแล้ว = ย้อนไม่ได้ ข้อความบอกให้ทำรายการแก้ไขพร้อมเหตุผลแทน) · ด่านเฉพาะ action (`undo.guard`) |
| `flags` | ธง/ข้อยกเว้น: "ระบบหาข้อยกเว้น คนตัดสิน" — ทีม · ความด่วน · เรื่อง · สถานะ เปิด/รับทราบ/ปิด · `dedupe_key` กันธงเดิมซ้ำ (เช่นรอบค้างเครื่องเดิม) · `req_key` = ย้อนคำขอที่ยกธง → ปิดธงให้เอง |
| `sync_runs` | รอบนำเข้า: แหล่ง · กี่หน้า · ใหม่/อัปเดต/ข้าม · ปัญหาที่เจอ (ข้อความไทย) |
| `import_map` | แถวต้นทาง → แถวในระบบ + ลายนิ้วมือเนื้อแถว — นำเข้าซ้ำกี่รอบก็ไม่เบิ้ล · เนื้อไม่เปลี่ยน = ข้ามโดยไม่เขียน |
| `counters` | เลขรันที่ต้องเรียงต่อกัน (เช่นเลขบิล — โมดูลบัญชีใช้) · รหัสแถวทั่วไปไม่ใช้ตัวนับ |

## 0002_customers — ลูกค้า + สายส่ง

- `routes`: สาย 111–121 (ใกล้) · 211–215 (ไกล) ตามทะเบียนเดิม · แก้จากหน้าจอ ไม่แก้โค้ด
- `customers`: `name_key` = ชื่อแบบหลวม (กติกาเดียวกับ `normName_` ใน `gas/Code.gs`) ใช้จับคู่ · `needs_review=1` = เกิดจากนำเข้าแล้วจับคู่ไม่ติด (ขึ้นธงให้ออฟฟิศรวม/ยืนยัน) · `merged_into` = รวมเข้ารายอื่นแล้ว (ไม่ลบ) · `note` = หมายเหตุการค้า ("เงินไม่ดีให้สั่งทางออฟฟิศ")
- `customer_aliases`: ชื่ออื่นของลูกค้าคนเดิม (สะกดต่าง · ชื่อจากออเดอร์เก่าที่ปนชื่องาน) — รอบหน้าจับคู่ตรงทันที
- จับคู่ (`server/import/legacy.mjs › matchCustomer`): ตรงตัว → ชื่ออื่น → ขึ้นต้นด้วยชื่อในทะเบียน (≥4 ตัว) → ชื่อย่อของทะเบียน (≥5 ตัว) · **กำกวม = ไม่จับ** (สร้างเป็น "รอตรวจ" + ธง ดีกว่าผูกผิดคน) · แยก "งาน…" ออกเป็น `orders.brand`

## 0003_products — สินค้า = สเปกหลายแกน

- `product_types`: ประเภท + แกนที่ใช้จริง (`axes` — ฟอร์มโชว์เฉพาะแกนเหล่านี้: ฟิล์มไม่มีช่องคอขวด) + หน่วยนับหน้างาน (ถุง/ชิ้น)
- `type_sizes`: ขนาดต่อประเภท + **ใบต่อถุง** + **ขั้นต่ำสั่ง** (ทุกตัวเลขจาก `PER_BAG`/`MIN_ORDER` ใน `gas/Code.gs` ที่ถอดจากออเดอร์จริง) · ขั้นต่ำ = เตือนอย่างเดียว ไม่บล็อก
- `spec_values`: ค่าของแกนอื่น (คอขวด · รูปทรง · สี · สีสกรีน · ฝาสี) · `grade='B'` = สี "ดำ (เกรด B)"
- `products`: ทะเบียน SKU 29 รายการ (`docs/products/products-master.csv`) — ราคาอ้างอิงจากบิลอยู่ในหมายเหตุ **ไม่ใช่ราคาตั้ง**
- `prices` + `price_history`: ราคาปัจจุบันต่อ `item_key` (`sku:…` หรือ `spec:…`) × ชนิดราคา (โรงงาน/หน้าร้าน/ไม่รวมฝา) · **ปรับได้เฉพาะบทบาท exec** · ทุกครั้งมีแถวประวัติใน batch เดียวกัน (โมดูลประธานทำ action `price.set`)
- กุญแจสเปก: `server/core.mjs › specKey()` = `ประเภท|ขนาด|คอขวด|รูปทรง|สี` (แกนที่ประเภทนั้นไม่ใช้ = ว่าง) — ใช้ตัวเดียวกันทุกที่ (ออเดอร์ · งานผลิต · รอบเครื่อง · สต๊อก · ราคา)

## 0004_orders — ออเดอร์

- ช่องที่พนักงานเคยเขียนปนในหมายเหตุ (43% ของออเดอร์) เป็นช่องจริง: `pay_status` · `design_status` · `block_fee_satang` · `urgent` · `done_bags`/`pending_bags`/`pending_reason` · `finished_day`
- `customer_text` เก็บชื่อตามต้นทาง (ตรวจย้อนได้ว่าจับคู่ถูกไหม) · `brand` = ชื่องาน/แบรนด์
- `pay_status` ว่าง = ไม่ระบุ (**ไม่เดาให้**) · `total_satang` NULL = ไม่ใส่ราคา (ระบบเดิมไม่คิดเงิน)
- `order_items`: 1 แถว = 1 สเปก · `made_pcs` / `delivered_pcs` ไว้ให้โมดูลขยับ (ทำแล้ว/ส่งแล้ว ต่อรายการ)
- สถานะ: รอผลิต → กำลังผลิต → รอสกรีน → กำลังสกรีน → พร้อมส่ง → ส่งบางส่วน → ส่งแล้ว / ยกเลิก (ชุดเดียวกับ `recomputeOrder_` ใน `gas/Code.gs`)

## 0005_production — เครื่อง · งานผลิต · รอบเครื่อง

- `machines`: ทะเบียน 49 รายการจากผัง (`v2/db/reference/factory.json` ← `docs/factory/README.md`) · ชนิด เป่า/ฉีด/สกรีน/ลม/น้ำเย็น/ไฟฟ้า/อื่น · ตำแหน่ง `pos_x/pos_y/w/h` (ร่าง รอผังจริง) · `legacy_name` = ชื่อในแอปงานผลิตเดิม (`SHE230G PET` → ยังไม่รู้ว่า K ตัวไหน)
- `production_jobs`: งานผลิตต่อสเปก — ผูกออเดอร์ได้ แต่ไม่บังคับ (ของเดิม "ผลิตเข้าสต๊อก")
- `machine_runs`: รอบเครื่อง = เริ่ม → (เปลี่ยนสี = ปิดรอบเดิม + เปิดรอบใหม่) → ปิดรอบ ลง ดี / เกรด B / เสีย · `counter_pcs` = ตัวนับจากเครื่องในอนาคต (คนไม่กรอก) · **unique index: เครื่องหนึ่งมีรอบ "กำลังผลิต" ได้รอบเดียว** (กดเปิดซ้อน/สองคนกดพร้อมกัน = ตัวหลังล้ม) · ข้ามเที่ยงคืนได้ (`ended_at ≥ started_at` · วันเริ่ม/วันปิดแยก)
- สถานะ `ค้างจากระบบเดิม` = รอบที่แอปเดิมค้าง "กำลังผลิต" (71 รอบ) — นำเข้ามาแบบไม่นับว่าเครื่องเดินอยู่ + ขึ้นธง "รอบค้าง"
- `run_operators`: ผู้ปฏิบัติงานหลายคนต่อรอบ (ของเดิมพิมพ์ "ไก่ , กานต์") — `name_text` ตามจริง + `staff_id` ถ้าจับคู่ได้
- `machine_events`: จอดเครื่อง (+สาเหตุจากชิป `reason.machine_stop`) · เปลี่ยนโมลด์ · ซ่อม — มีช่วงเวลา
