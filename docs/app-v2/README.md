## 2. หลักหน้าจอ (บังคับทุกหน้า — ย่อจาก PALM-WAY ทั้งสอง repo)

- มองแวบเดียวรู้: ตัวเลขสำคัญใหญ่สุด · จำนวน = ป้าย `[ขนาด | ตัวเลขหนา หน่วย]` เรียงเล็ก→ใหญ่ · สถานะ = สี+คำ+สัญลักษณ์ · **ไม่โชว์รหัสระบบบนจอ** (อ้างด้วย ร้าน·วันที่·ยอด·ใคร · รหัสอยู่บรรทัด "รหัสอ้างอิง" จาง ๆ ในรายละเอียดที่เดียว)
- หน้าแรก = งานที่รอ · ไม่มีงาน = "ไม่มีงานค้าง" · เมนู ≤5 · งานทุกวันกดถึงทีเดียว · เปิดแอปเริ่มหน้าแรกเสมอ · ← กลับหน้าก่อนจริง
- หน้าที่มีงานเดียว: ยอดหลักใหญ่สุด + ปุ่มหลักปุ่มเดียวติดท้ายแผ่น เห็นโดยไม่ต้องเลื่อน · ของนาน ๆ ใช้พับใน "ตัวเลือกเพิ่มเติม"
- กดแทนพิมพ์ · ตัวที่เกี่ยวข้องสุดขึ้นก่อนแต่ค้นได้ · รายการให้แตะต้องมี "อื่น ๆ (พิมพ์เอง)" · แป้นตัวเลขของแอปเอง ปุ่ม ≥44px
- รายละเอียด = แผ่นล่างลากขึ้นแบบ Google Maps · ถามยืนยันด้วยแผ่นในแอป + ชิปเหตุผล (ห้าม alert/confirm/prompt)
- ไม่มีทางตัน: เคสแปลกทำต่อได้ + เหตุผล + AuditLog + ธง · ด่านกันพลาด 3 ระดับ (ผิดแน่+เสียเงิน = บล็อก เหลือทางผ่านให้ผู้จัดการ/การเงิน · เปลี่ยนแผน = ยืนยันปุ่มเดียวบอกผล · ตัวเลขในด่าน = ตัวเลขที่ผู้ใช้เห็น) · ถูกบล็อกต้องบอกในจอเดียวว่าเห็นอะไร+ต้องกดอะไร+ปุ่มพาไป
- ทุกปุ่มบันทึก **ย้อนได้** จนกว่าขั้นถัดไปรับไป (แถบ "ย้อน" หลังบันทึก) · ย้อน = พลิกสถานะ **ไม่ลบแถว**
- เงิน: ไม่มีค่าตั้งต้นเดา · ยอดเงินบอกช่วงเวลาเสมอ · ตัวเลขเงิน/ของรอข้อมูลจริง (ห้ามขึ้น ฿0 ตอนโหลดไม่สำเร็จ)
- จอไม่โกหก: โหลด/ส่งไม่สำเร็จบอกตรง · หน้าใช้ทุกวัน "ไม่กระพริบ ไม่เด้ง" (โชว์ของรอบก่อน แล้ววาดใหม่เฉพาะที่เปลี่ยน)
- ของที่เครื่องวัดได้ห้ามให้คนกรอก (มิเตอร์/ตัวนับในอนาคต) · ระบบลงให้เองได้เมื่อมีหลักฐาน
- ไม่มีชนชั้นบนจอ · สิทธิ์กรอง 2 ชั้น (หน้าจอ + เซิร์ฟเวอร์) · ชื่อคนทำมาจากตั๋ว/ตาราง staff เท่านั้น ไม่เชื่อหน้าเว็บ
- ไอคอน SVG ชุดเดียว ไม่ใช้อีโมจิ · ไม่มีศัพท์นักพัฒนา · ภาษาไทยทั้งหมด
- ทดสอบจอ 320 · 360×640 · 390×844 · 1366×768 · WCAG AA · reduced-motion · ของใหม่ห้ามเริ่มด้วยป๊อปอัปเด้งเอง
- สีโรงขวด = แดงอิฐ (ไม่ใช่ธีมกระจก — โรงน้ำรื้อกระจกแล้ว "ไม่อ่อน") · สถานะ เขียว/อำพัน/แดง ความหมายเดียวกับโรงน้ำ

## 3. สถาปัตยกรรม (ตัดสินแทนคุณปาล์ม 16 พ.ย. — ย้อนได้ · เหตุผล: คุณปาล์มอยากได้ Cloudflare "จะได้ไวกว่า" + โรงน้ำตัดสิน "ยกทั้งระบบ" ไป D1 และระบบใหม่ของโรงน้ำสร้างบน D1 ตั้งแต่แรก)

- **Cloudflare Pages (PWA) + Pages Functions (API) + D1 = ตัวจริงของข้อมูล v2** · โปรเจกต์/ฐานข้อมูล **แยกจากโรงน้ำเด็ดขาด** (ชื่อขึ้นต้น `pk-`)
- **Google = สะพานเท่านั้น** ผ่าน GAS P&K System (`gas/Code.gs`):
  1. ตรวจ PIN จากชีต Staff แล้วออก **ตั๋ว HMAC** (กุญแจร่วม GAS Script Properties + CF secret) — **PIN ห้ามขึ้น Cloudflare** (แบบโรงน้ำ: ตรวจที่ GAS ครั้งเดียว ตั๋วอายุ ~30 วัน ผูกลายนิ้วมือ PIN → เปลี่ยน/พัก = ตั๋วตาย)
  2. ส่งข้อมูล **อ่านอย่างเดียว** จากชีต (PKSystem · ระบบบัญชี · Order · Stock Management · P&K_ลูกค้า) ขึ้น D1 เพื่อนำเข้า/ซิงก์ช่วงเปลี่ยนผ่าน — **ห้ามเขียนกลับชีทบัญชีและชีต AppSheet เด็ดขาด**
  3. ภายหลัง (ตอนสลับใช้จริง): กระจก D1 → ชีต PKSystem ให้ palm-hq/คนเปิดดู (`Bills`/`Statements` หัวคอลัมน์เดิม — เปลี่ยนต้องถาม)
- P&K System ปัจจุบัน (GitHub Pages + GAS) **รันต่อเหมือนเดิม** จนกว่าทีมนั้นย้าย · v2 ห้ามทำให้ของเดิมพัง
- **ทำงานบน branch `pk-app-v2` เท่านั้น ห้ามแตะ `main`** (push main = deploy GAS + Pages จริง) · แก้ `gas/Code.gs` บน branch นี้ได้ แต่ยังไม่ deploy จนคุณปาล์มอนุมัติ
- ยังไม่มีกุญแจ Cloudflare ใน repo นี้ → ทุกอย่างต้อง **รัน/เทสต์ในเครื่องได้ครบ** (wrangler/miniflare หรือ SQLite แทน D1) · deploy job เขียนไว้แต่ข้ามเองถ้าไม่มี secret
- ความลับ: ห้าม hardcode/commit คีย์ · ข้อมูลจริงห้ามลง repo (Pages สาธารณะ) · seed/mock ใช้ข้อมูลสมมติ

## 4. ข้อตกลงโค้ด (ให้ทุกแชทเหมือนกัน)

- โฟลเดอร์: `v2/` = ทั้งแอป (web · functions · server · db · tests · tools) — โครงละเอียดกำหนดโดยแชท Foundation แล้วจดไว้ใน `v2/README.md`
- API: ประตูเดียว (router) + รายชื่อ action ที่อนุญาตต่อบทบาท · ทุกคำขอต้องมีตั๋ว (ยกเว้น health/login) · ผู้กระทำ = จากตั๋ว
- เขียนข้อมูล: 1 action = 1 D1 batch ที่มีแถว `audit_log` (ใคร · เมื่อ · action · entity · ก่อน · หลัง · เหตุผล) อยู่ใน batch เดียวกัน · **ไม่มี DELETE** (พลิกสถานะ) · idempotency key กันกดซ้ำ · optimistic version กันทับกัน
- เงิน = จำนวนเต็มหน่วยสตางค์ · จำนวนสินค้า = จำนวนเต็มหน่วย "ใบ/ชิ้น" (ถุงคิดจาก per_bag) · เวลา = ISO UTC + คอลัมน์วันที่ไทย (UTC+7 คงที่)
- migration: `v2/db/migrations/NNNN_*.sql` ช่วงเลข: 0001–0099 Foundation · 0100–0199 ผลิต · 0200–0299 ออฟฟิศ · 0300–0399 สกรีน+ส่งของ · 0400–0499 ประธาน+บัญชี
- เทสต์ทุก action (ถูก/ผิดสิทธิ์/ซ้ำ/ย้อน/ชนกัน) + เทสต์หน้าจอ Playwright ที่ 390 และ 1366 · CI รันบน push `pk-app-v2`
- ทำเสร็จแต่ละแชท: อัปเดต `docs/app-v2/STATUS.md` (เขียนทับส่วนของตัวเอง) + ภาพหน้าจอ + publish artifact ส่วนตัว "พรีวิว UI" (ข้อมูลสมมติ) ใส่ลิงก์ในรายงาน

## 5. ลำดับ + แชทย่อย

1. **Foundation** (เริ่ม 16 พ.ย.): โครง repo v2 · ระบบดีไซน์ (ยก `gen_tokens.py` ของโรงน้ำมาใช้สีแดงอิฐ) · ชิ้นส่วน UI กลาง · เปลือกแอป+เมนูตามบทบาท · ตั๋ว/PIN ผ่าน GAS · สคีมาโดเมนทั้งหมด v1 · สะพานนำเข้าข้อมูล · ทะเบียนสินค้า/เครื่อง/ลูกค้า · เทสต์ + CI
2. หลัง Foundation ลง `pk-app-v2` → แตกพร้อมกัน: **ทีมผลิต** (แผนผัง+รอบเครื่อง) · **ออฟฟิศ** (ออเดอร์ทั้งวงจร) · **สกรีน+ส่งของ** · **ประธาน+บัญชี**
3. ทีละทีมย้ายเข้าใช้จริง (ต้องให้คุณปาล์มสั่ง) · ปิด AppSheet ทีมนั้น (คุณปาล์มสั่ง)
4. มิเตอร์ไฟ/ข้อมูลเครื่อง (เมื่อมีอุปกรณ์)
5. **ชั้นวางแผน** (แผนสายส่ง 7 วัน → ขวดที่ต้องมี → ใบงานเป่า/สกรีน · ซ่อมบำรุง · ตัววัด) — สเปก + ลำดับพัฒนาใน [`PLANNING.md`](PLANNING.md) (17 พ.ย.)
