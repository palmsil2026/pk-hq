## 5. งานถัดไป (แนะนำลำดับ)

1. **ปฏิทินสายส่ง 7 วัน เข้าแอปจริง** — ใช้ต้นแบบเป็นแบบหน้าจอ แต่ข้อมูลจริง: งวดส่ง · หมุด/สาย (`route_areas`) · ลำดับคิวกลาง · สต๊อก
   - คนใช้จริง = **หัวหน้าทีมสกรีน + ผู้ช่วย** (ไม่ใช่ออฟฟิศ) · หน้าตาเป็นปฏิทินเรียง 7 วัน หมุดสายต่อวัน · อำเภอเมืองส่งได้ทุกวัน · ในวันมีแค่ ลูกค้า · สินค้า · จำนวน
   - ต่อด้วย "ขวดที่ต้องมี" (ต้องเป่าเพิ่ม/ต้องสกรีน ก่อนวันไหน) + ประกาศแผนเป็นข้อความแชร์ลงไลน์ (ไม่ส่งอัตโนมัติ)
   - migration ใช้ช่วง **0500–0599** (ชั้นวางแผน)
2. ใบงานเป่าพรุ่งนี้ต่อเครื่อง + ใบงานสกรีนต่อวัน จาก "ขวดที่ต้องมี" (PLANNING ขั้น 3–4)
3. เช็คของพร้อมต่อคันรถ + พิมพ์ทั้งคัน + Checker ติ๊ก
4. ซ่อมบำรุง (ขั้น 5)

ก่อนเริ่มแต่ละข้อ: ทำหน้าจอให้คุณปาล์มดูก่อน (ภาพมือถือ 390 + คอม 1366) เพราะ UX มักถูกปรับหลังเห็นของจริง

## 6. กติกาที่ห้ามพลาด

- **ห้าม push / merge เข้า `main` เองโดยไม่ได้รับอนุญาต** (push main = หน้าเว็บขึ้นจริง + GAS deploy อัตโนมัติ)
- **ห้ามเขียนกลับชีต "ระบบบัญชี"** และชีตของ AppSheet เดิม — อ่านอย่างเดียวเท่านั้น
- **ห้ามใส่ความลับใน repo** (กุญแจอยู่ GitHub Secrets / Script Properties) · **ห้ามข้อมูลลูกค้าจริง ยอดเงินจริง ชื่อพนักงานจริง** ใน repo (repo สาธารณะ) — ข้อมูลทดสอบสมมติเท่านั้น
- ห้ามปนข้อมูลกับโรงน้ำ (`origin-hq`) และร้านกาแฟ — คนละบริษัท
- โค้ด v2: ไม่มี `DELETE` · ทุกการเขียนผ่าน ops + audit log · idempotency key · version กันชน · ย้อนได้ · เงินเป็นสตางค์ · เคสแปลก = ทำได้ + เหตุผล + ธง (ไม่บล็อก) · เรื่องเงินห้ามเดาแทนคน
- หน้าจอ: ผ่าน 320 / 360 / 390 / 1366 + โหมดมืด · ปุ่ม ≥ 44px · ไม่มีอีโมจิ/รหัสระบบ/ศัพท์นักพัฒนาบนจอ · **ของใหม่ห้ามกดมากกว่าของเดิม** (เช่น ทีมสกรีนต้องจบใน 2 แตะ)
- **§9 ต้องถามคุณปาล์มก่อน**: นโยบายเงิน · ขยายการเห็นตัวเลขเงิน · ลบ/แก้ชีตจริง · ข้อความออกหาลูกค้าครั้งแรก · ราคาสินค้า · ปิดแอปเดิม
- แก้ `.html` ของ main → ขยับ `WEB_VERSION` · แก้ `gas/Code.gs` → ขยับ `CODE_VERSION` · v2 มี `WEB_VERSION` ของตัวเองใน `v2/web`
- เจอบทเรียนใหม่จากคุณปาล์ม → เพิ่มลง `PALM-WAY.md` ในรอบเดียวกัน · สถานะ → เขียนทับหัวข้อของตัวเองใน `docs/app-v2/STATUS.md`
